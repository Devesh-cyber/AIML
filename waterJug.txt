AIML PRACTICAL NOTES
Water Jug Problem — State-Space Search using BFS

1. AIM OF THE PROGRAM
The aim is to generate and display all reachable states of the Water Jug Problem using Breadth-First Search (BFS).

In this example:
- Jug 1 capacity = 4 litres
- Jug 2 capacity = 3 litres
- Initial state = (0, 0)
- No target quantity is specified, so the program explores all reachable states and stops when no new states remain.

2. WHAT IS A STATE?
A state is written as (x, y), where:
- x = amount of water in the 4-litre jug
- y = amount of water in the 3-litre jug

Examples:
- (0, 0): both jugs are empty
- (4, 0): 4-litre jug is full; 3-litre jug is empty
- (1, 3): 1 litre in the first jug and 3 litres in the second jug
- (4, 3): both jugs are full

3. STATE-SPACE
The state-space is the collection of possible states of the problem.

For a 4-litre and 3-litre jug:
- Jug 1 can contain 0, 1, 2, 3, or 4 litres: 5 possibilities.
- Jug 2 can contain 0, 1, 2, or 3 litres: 4 possibilities.
- Maximum theoretical combinations = 5 × 4 = 20.

However, not every combination is necessarily reachable using the allowed operations from the initial state (0, 0). In this example, 8 states are reachable.

4. ALLOWED OPERATIONS
There are six operations:

1) Fill Jug 1:
   (x, y) -> (4, y)

2) Fill Jug 2:
   (x, y) -> (x, 3)

3) Empty Jug 1:
   (x, y) -> (0, y)

4) Empty Jug 2:
   (x, y) -> (x, 0)

5) Pour water from Jug 1 into Jug 2:
   Transfer as much as possible without overflowing Jug 2 or taking more than Jug 1 contains.

6) Pour water from Jug 2 into Jug 1:
   Transfer as much as possible without overflowing Jug 1 or taking more than Jug 2 contains.

5. POURING FORMULAS
For pouring from Jug 1 (4L) to Jug 2 (3L):

amount = min(x, 3 - y)

Next state:
(x - amount, y + amount)

Explanation:
- x is the water available in Jug 1.
- 3 - y is the free capacity in Jug 2.
- min() chooses the smaller value, so we neither transfer more water than is available nor overflow the destination jug.

For pouring from Jug 2 (3L) to Jug 1 (4L):

amount = min(y, 4 - x)

Next state:
(x + amount, y - amount)

Explanation:
- y is the water available in Jug 2.
- 4 - x is the free capacity in Jug 1.
- The source loses the transferred amount and the destination gains it.

6. WHAT IS BFS?
BFS stands for Breadth-First Search.

It explores states level by level, using a FIFO (First In, First Out) queue:
- The state added first is processed first.
- It explores states in the order they are discovered.
- BFS is commonly used for unweighted state-space search.

Python's deque is used as the queue:
    from collections import deque

7. PURPOSE OF IMPORTANT VARIABLES
- jug1 = 4: capacity of the first jug.
- jug2 = 3: capacity of the second jug.
- queue = deque([(0, 0)]): starts the search from the empty state.
- visited = set(): stores states already processed.
- x, y: current amounts of water in the two jugs.
- states: list of states generated by applying the six operations.

Why use visited?
A state may be reached through different operation sequences. The visited set prevents processing it repeatedly and helps avoid endless cycles.

8. CORRECTED PYTHON CODE
from collections import deque

jug1 = 4
jug2 = 3

queue = deque([(0, 0)])
visited = set()

while queue:
    x, y = queue.popleft()

    if (x, y) in visited:
        continue

    visited.add((x, y))
    print((x, y))

    states = [
        (jug1, y),  # Fill Jug 1
        (x, jug2),  # Fill Jug 2
        (0, y),     # Empty Jug 1
        (x, 0),     # Empty Jug 2
        # Pour Jug 1 into Jug 2
        (x - min(x, jug2 - y), y + min(x, jug2 - y)),
        # Pour Jug 2 into Jug 1
        (x + min(y, jug1 - x), y - min(y, jug1 - x))
    ]

    for state in states:
        if state not in visited:
            queue.append(state)

Note: The fill operations are written as (jug1, y) and (x, jug2), because filling one jug should preserve the current amount in the other jug. The empty operations are written separately.

9. PSEUDOCODE
START

Set capacity of Jug 1 = 4
Set capacity of Jug 2 = 3

Create a queue and insert initial state (0, 0)
Create an empty visited set

WHILE queue is not empty:

    Remove the first state (x, y) from the queue

    IF (x, y) is already in visited:
        Continue to the next iteration

    Add (x, y) to visited
    Display (x, y)

    Generate the six possible next states:
        1. Fill Jug 1
        2. Fill Jug 2
        3. Empty Jug 1
        4. Empty Jug 2
        5. Pour Jug 1 into Jug 2
        6. Pour Jug 2 into Jug 1

    FOR each generated state:
        IF it is not in visited:
            Add it to the queue

END WHILE

STOP

10. EXPECTED OUTPUT
(0, 0)
(4, 0)
(0, 3)
(4, 3)
(1, 3)
(3, 0)
(3, 3)
(4, 2)

The order is the BFS discovery/processing order for this successor ordering.

11. UNDERSTANDING THE OUTPUT
- (0, 0): initial state; both jugs are empty.
- (4, 0): fill the 4L jug.
- (0, 3): fill the 3L jug.
- (4, 3): both jugs are full.
- (1, 3): pour from (4, 0) into the 3L jug. Three litres move, leaving 1 litre in Jug 1.
- (3, 0): pour from (0, 3) into the 4L jug; the 3L jug becomes empty.
- (3, 3): fill Jug 2 from (3, 0).
- (4, 2): from (3, 3), pour from Jug 2 into Jug 1. Jug 1 has room for 1 litre, so 1 litre transfers and the state becomes (4, 2).

12. IMPORTANT CONCEPT: START STATE
The search begins at the state placed in the queue.
- Starting from (0, 0) means exploring states reachable from two empty jugs.
- Changing the initial state changes where the search begins and may change the reachable set in some problems.
- For this 4L/3L jug setup, the reachable states can connect back through allowed actions, so starting elsewhere among these reachable states may produce the same reachable component, although the output order can differ.
- The 20 theoretical combinations are based on capacities; the program prints only states reachable from its chosen start using the allowed operations.

13. WHEN DOES THE PROGRAM STOP?
There is no goal test such as “amount equals 2 litres” in this version.
The program stops when the queue becomes empty, meaning no unprocessed reachable states remain.

14. VIVA QUESTIONS AND SHORT ANSWERS

Q1. Which algorithm is used?
Breadth-First Search (BFS).

Q2. Why is a queue used?
BFS uses FIFO order: the first inserted state is processed first.

Q3. Why is a visited set required?
To avoid processing the same state repeatedly and to prevent cycles.

Q4. How many operations are possible?
Six: fill either jug, empty either jug, and pour in either direction.

Q5. What does (x, y) represent?
The water quantities in the 4L jug and 3L jug, respectively.

Q6. Why is min() used in the pouring formula?
To ensure we transfer only the available water or the destination's free capacity, whichever is smaller.

Q7. How many theoretical states are possible?
(4 + 1) × (3 + 1) = 20.

Q8. Why does the output contain only 8 states?
Only 8 states are reachable from (0, 0) using the defined operations.

Q9. What is the initial state?
(0, 0), meaning both jugs are empty.

Q10. When does the program terminate?
When the queue is empty and no new reachable states remain to process.

Q11. Is this code finding a particular target amount?
No. It generates all reachable states; no goal condition is included.

Q12. What is the difference between theoretical and reachable states?
Theoretical states are all capacity-valid combinations. Reachable states are those that can actually be generated from the start using the allowed operations.
